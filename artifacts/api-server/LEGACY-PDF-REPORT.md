# Предварительная инвентаризация исторических PDF

Команда `pnpm report:legacy-pdfs` **только читает** хранилище и создаёт HTML/JSON.
Флагов удаления, входа в cleanup worker и выдачи новых разрешений у неё нет.
Автоматическая очистка по-прежнему обходит общую папку `uploads`.

## Что установлено при исследовании

- До внедрения привязанных разрешений API сохранял присланный клиентом путь.
  `orders.pdf_path` — основание сохранить файл, не доказательство выдачи загрузки
  именно для заказа.
- Старые выдачи URL не сохраняли путь/поколение/срок разрешения в таблице аудита.
  При копировании в `order-pdfs` также не записывалась история исходного пути.
- Журналы приложения сохраняли метод, URL запроса и статус, но не выдаваемые
  пути или связь источника с итоговым PDF.
- Архивы `/api/backup/export` содержат каталог и настройки, не заказы и историю PDF.
- MIME, сигнатура PDF, UUID, возраст, пользовательские метаданные и совпадение
  содержимого/хешей **не доказывают принадлежность**. Метаданные подписанного
  PUT могут задаваться клиентом.

Поэтому отчёт не помечает исторические файлы как разрешённые к удалению.
Срок разрешений остаётся неподтверждённым даже у файлов старше 24 часов.
Не найденные ссылки в снимках не означают, что файл никому не нужен.

## Повторный запуск

1. Выполнить запрос из `legacy-order-pdf-references.sql` **только на чтение**
   через инструменты базы отдельно для `development` и `production`.
   Production читается через поддерживаемую реплику, не через строку подключения.
   Запрос проверяет все строки/вложенные JSON-значения заказов, товаров и настроек,
   извлекает все ссылки в каждой строке и учитывает URL с `%2F` вместо `/`.
   В отчёт попадают только нормализованные пути UUID, без клиентов, токенов,
   подписанных URL и имён бакетов.
2. Собрать два возвращённых JSON-объекта в массив, добавив каждому
   `"environment": "development"` или `"environment": "production"`.
   Сохранить вне репозитория, например `/tmp/legacy-pdf-references.json`.
   Не выдавать ошибку запроса или пустой ответ за успешный снимок.
3. Из корня выполнить:

   ```sh
   pnpm report:legacy-pdfs \
     --references /tmp/legacy-pdf-references.json \
     --output "$PWD/reports/legacy-order-pdfs.html"
   ```

Отчёт отказывается работать без обоих полных снимков, при возрасте снимка
более часа, ошибке листинга или метаданных. Это снимок, а не блокировка:
ссылки и объекты могут измениться после его формирования. Отсутствующий в
инвентаризации путь из базы отображается отдельно и не считается кандидатом.

## Что потребуется для удаления исторического файла

Нужен явно подтверждённый список и независимый серверный источник:
например, защищённая история выдачи разрешений с точным путём и поколением,
привязкой к заказу, назначением временного PDF и максимальным сроком всех
разрешений. Одно утверждение в метаданных или ручной JSON-манифест не считается
таким источником. Ретроспективно восстановить отсутствующую историю из MIME нельзя.

После проверки доказательств необходимы повторная проверка всех ссылок в
обоих окружениях, проверка фактических сроков разрешений и поколения,
согласование с активными писателями и условное удаление именно проверенного
поколения. Старые опубликованные версии приложения могли не использовать
совместную блокировку — её наличие только в новом коде не гарантирует
безопасность старых загрузок. При недоступной базе, неизвестном происхождении,
активном разрешении или изменённом объекте удаление запрещено.

Текущий инструмент намеренно не реализует этот шаг и не расширяет
`cleanupOrderPdfs`. Пока проверяемых доказательств нет, безопасный результат —
сохранить все исторические загрузки.
